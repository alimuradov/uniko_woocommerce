# Проект UNIKO WooCommerce

## Обзор проекта

Этот проект предназначен для выгрузки остатков товаров из учетной системы UNIKO и загрузки их на веб-сайт, используя платформу WordPress с установленным плагином WooCommerce. При выгрузке создаются товары и вариации товаров, а также выгружаются категории.

Проект работает с двумя аптечными сетями:
- Основная сеть (Аптека 149) - данные из файла `ost.dbf`
- Вторая аптечная сеть (Панацея) - данные из файла `agasieva.dbf`

## Архитектура проекта

```

```

### Основные компоненты

#### main.py
Основной скрипт, который:
- Читает DBF файлы с остатками товаров из UNIKO
- Объединяет данные из двух аптечных сетей
- Создает категории, атрибуты и значения атрибутов в WooCommerce
- Создает и обновляет товары в соответствии с остатками

#### utils/woocommerce.py
Содержит конфигурацию WooCommerce API с использованием библиотеки WooCommerce REST API.

#### utils/api.py
Содержит основные функции для взаимодействия с WooCommerce:
- Создание/обновление категорий
- Создание/обновление атрибутов
- Создание/обновление товаров
- Обработка остатков и цен

#### utils/utils.py
Вспомогательные функции:
- Транслитерация русских названий аптек в латинские slug'и
- Группировка продуктов по коду
- Работа с атрибутами и метаданными
- Расчет остатков и цен

#### utils/func.py
Функции для генерации slug и очистки строк от нецифровых символов.

## Зависимости

Проект использует следующие основные зависимости:
- `dbfread` - для чтения DBF файлов
- `python-dotenv` - для работы с переменными окружения
- `WooCommerce` - для взаимодействия с WooCommerce REST API
- `transliterate` - для транслитерации кириллических текстов

## Переменные окружения

Для работы проекта требуются следующие переменные окружения:

```env
API_URL=http://your-wordpress-site.com
WOO_KEY=your_woocommerce_consumer_key
WOO_SECRET_KOD=your_woocommerce_consumer_secret
FILES_CATALOG_PATH=/path/to/dbf/files
TB_BOT_TOKEN=optional_telegram_bot_token
TG_CHAT_ID=optional_telegram_chat_id
```

## Формат DBF файлов

Проект ожидает два DBF файла в каталоге, указанном в `FILES_CATALOG_PATH`:
- `ost.dbf` - основные остатки товаров
- `agasieva.dbf` - остатки второй аптечной сети

Каждый файл должен содержать следующие поля:
- `NAMETMC` - Наименование товара
- `OST` - Остаток товара
- `PRICE` - Цена
- `MNN` - Международное непотентованное название
- `NAMEPODR` - Название аптеки
- `ISRECEPT` - Рецептурный признак
- `FARMGROUP` - Фармгруппа
- `MEASURE` - Единица измерения
- `DELUPAK` - Количество единиц в упаковке
- `ISLIFE` - ЖНВЛ (жизненно необходимые лекарственные препараты)
- `GROUP` - Группа товара
- `CODTMC` - Код товара
- `FACTORY` - Производитель
- `CATEGORY` - Категория товара
- `DATEVALID` - Срок годности
- `BRAND` - Бренд
- `PRICEDELI` - Цена закупки
- `SCANCOD` - Штрихкод

## Запуск проекта

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

2. Настройте переменные окружения в файле `.env`

3. Поместите DBF файлы в каталог, указанный в `FILES_CATALOG_PATH`

4. Запустите основной скрипт:
   ```bash
   python main.py
   ```

## Особенности реализации

- Проект обрабатывает данные из двух аптечных сетей, объединяя их по штрихкоду
- Для товаров с одинаковым штрихкодом из разных сетей создаются разные вариации
- Реализована пакетная обработка товаров для повышения производительности
- При обновлении товаров, которых нет в новых остатках, они снимаются с продажи
- Поддерживается расчет общего остатка по всем аптекам
- Используется транслитерация русских названий аптек для генерации slug'ов
- Реализована обработка ошибок и задержки при проблемах с API
